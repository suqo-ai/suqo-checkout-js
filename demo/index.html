Merchant page (demo)

A deliberately ugly host page with loud global CSS. The payment block below renders inline, in this page's own flow — there is no modal and no overlay. Serve this from a different origin than the checkout to exercise the cross-origin path.

The block renders into whichever element this page names — elementId: 'my-payment-area' below — rather than an id fixed by the SDK. Everything else it needs is an HTML attribute; no JavaScript here builds or mounts it. The only script is the callbacks, which have to live here because they are the merchant's own business logic.

The block never announces an outcome. When a payment settles it shows a spinner and reports the result to onSuccess / onFailure; what the buyer is told, and where they go next, is entirely this page's decision. Here any failure or cancellation redirects to failed.html.

The whole integration

A checkout session is created by the merchant's backend with their API key, and already carries the buyer — so nothing about the customer appears on this page at all. One attribute. Mounts on load.
